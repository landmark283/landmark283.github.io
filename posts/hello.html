建站记：用 GitHub Pages 放一个个人主页

2026-10-20 · 建站

这个站点的全部内容，就是几个 HTML 文件加一份 CSS，放在一个叫 landmark283.github.io 的仓库里。没有数据库，没有服务器，也没有构建流程。

为什么是静态的

静态站点有个很朴素的优点：它不会坏。没有进程要重启，没有依赖要升级，也没有数据库哪天连不上。文件在那儿，页面就在那儿。代价是它做不了需要服务端的事——评论、登录、点赞，这些得另想办法（常见做法是接 giscus 这类基于 GitHub Issues 的评论框）。

GitHub Pages 到底做了什么

它只做两件事：把你仓库里的文件当静态服务器发出去，以及替你的域名签一张 TLS 证书。页面怎么来的它不管——手写、脚本生成、用 Hugo 或 Astro 构建，都一样。

用户站的仓库名必须是 <用户名>.github.io，这样网址才是域名根路径。如果把站点放在普通项目仓库里，它会挂在 /仓库名/ 下面，所有绝对路径都得跟着改，很麻烦。

三步

  1. 建一个公开仓库，名字是 landmark283.github.io。
  2. 根目录放 index.html，再加一个空的 .nojekyll（有它，GitHub 才不会拿 Jekyll 去处理你的文件）。
  3. Settings → Pages → Source 选 main 分支的 / (root)，保存。

一分钟左右，https://landmark283.github.io 就通了。之后每次 git push 都会自动重新发布。

顺带一句：别为了开 Pages 把自己项目仓库改成公开。私有仓库在免费账户下确实不能开 Pages，但更稳妥的做法是另建一个公开仓库，只放构建好的静态产物。

现在多了个构建脚本

文章都写成 Markdown，放在 docs/ 里，跑一遍 node build.mjs 就会生成对应的 HTML 和两个列表页。这一步只依赖 Node 内置模块，没有 node_modules，也不联网。
